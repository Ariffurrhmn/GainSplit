- **2026-11-10** Implementation choices for A1 (written 2026-11-10, owner to review): [CLS] vector without BERT's pooling layer (as GAN-BERT); AdamW, weight decay 0.01 (not on bias/LayerNorm), linear warm-up 10% then linear decay, gradient clipping 1.0, batch 32, fp16 on GPU. Learning rate chosen from {2e-5, 3e-5, 5e-5} with A1 at 10%, seeds 0-2, by mean dev macro-F1; if two are within about one std, take the smaller. Tuning runs score dev only. Resume is per run (a finished run is skipped) instead of per-epoch checkpoints, because one run takes minutes, not hours; this replaces the "checkpoint every epoch" line in [[Experiment Plan]]. Model weights are not saved; predictions are. Metrics: accuracy, macro-F1 (main), F1 of the sarcastic class (iSarcasmEval's official metric), ROC-AUC.
- **2026-11-10** CONFIRMED by owner: learning rate 5e-5 for every arm (now the default in `src/gainsplit/config.py`). Evidence: `lr_tuning` (A1, p = 10%, seeds 0-2, dev only; commit 29e4220): mean dev macro-F1 2e-5 0.8625 (sd 0.0112), 3e-5 0.8595 (0.0063), 5e-5 0.8673 (0.0053). 5e-5 beats 3e-5 on all three seeds and 2e-5 on two of three, has the best worst seed and the best dev ROC-AUC on every seed. The logged tie rule ("within about one std, take the smaller") is ambiguous here: the 0.005 gap is inside 2e-5's sd but not 5e-5's, and the smaller lr is the less stable one. 5e-5 is the top of the standard BERT grid; it is not extended further.

- **2026-11-10** DELEGATED: **A7 spec approved as proposed** (single-step L2-normalised FGM on word embeddings, loss = clean + adversarial, epsilon from {0.5, 1, 2} on dev at p = 10%; no label smoothing, R-Drop or layer freezing). - **2026-11-10** DELEGATED: **A3/A4/A5 implementation.** (1) Every step uses one L batch and, for U-arms, one U batch of the same size (32), so all arms keep the same step count while U-arms see unlabeled text each step. (2) Helper heads are linear layers on the shared [CLS] vector (3 sentiment, 5 emotion classes), trained on teacher **hard** labels over L+U, total helper loss = w x (sentiment CE + emotion CE), one w for both. Why hard labels: Part 2 varies label form (soft, weighted, ...) against this reference. (3) A4 follows GAN-BERT (Croce et al. 2020): 100-d noise generator MLP, (k+1)-class discriminator MLP on [CLS], supervised + real/fake losses, generator with feature matching. **Clean variant:** the discriminator step uses detached fakes, the generator step updates only the generator. Why: the reference code lets generator-loss gradients reach the discriminator, which mixes the two objectives; the clean form is the textbook GAN and easier to defend. No replication of labeled examples (GAN-BERT's log-scale trick): the fixed L batch per step already balances L against U. (4) A5 = A4 + the A3 helper losses on real vectors. (5) Training curves (loss terms, mean fake-probability on real vs fake) saved per run to check the GAN trains.
- **2026-11-10** DELEGATED: **next Kaggle session = `session2`** (12 runs, dev only): `w_tuning` (A3, p = 10%, w in {0.1, 0.3, 1.0}, seeds 0-2) and `gan_pilot` (A4, p = 10%, seeds 0-2). GAN pilot passes if dev macro-F1 is near A1's 0.867 and the discriminator keeps real and fake apart without collapsing; if it fails, fix before Pass 1 rather than report a broken GAN.
- **2026-11-10** DELEGATED: **gold audit protocol.** 200 training headlines drawn by the labeling app itself (rows sorted by id, Fisher-Yates shuffle with seeded PRNG mulberry32, seed 20261110), so the sample is reproducible and the owner draws it. Labeler sees only the headline (no sarcasm or teacher label: blind). Gold = **surface sentiment** (plain reading, ignore sarcastic intent), 3 classes, plus an "unsure" flag. Why surface: that is the task the teacher model was trained for, so the audit measures teacher error, not the gap between literal and intended meaning. Report teacher accuracy and macro-F1 on all 200 and on non-unsure items, per class. App: `experiments/gold_audit.html`, offline, data never leaves the browser.
- **2026-11-10** DELEGATED, review of the A3/A4/A5 code: (1) feature-matching loss averaged over the hidden features (not summed), as in the released GAN-BERT code; the sum is 768x larger and would let feature matching drown the generator's "fool D" term. (2) Supervised discriminator loss uses log-softmax over all k+1 outputs (true class only on L rows); prediction uses the first k outputs. The released PyTorch code takes log-softmax over the k real outputs only; both are used in the literature, ours also pushes labeled rows away from "fake", consistent with the real/fake loss. Stated as part of the re-implementation. (3) Gradient clipping 1.0 for both optimizers (GAN-BERT does not clip); kept for parity with A1/A3. (4) The generator's backward also leaves gradients on the discriminator; they are zeroed so the discriminator step only ever sees its own loss.

Why: (1) one annotator who knows the hypotheses is a reviewer target; independent extra annotators remove that and give an agreement number; (2) anonymous testers cannot be described in the paper (language, expertise), cannot be checked for random clicking, and raise consent and compensation questions; (3) annotators get only the 200 sampled headlines (id, text), never the full dataset or the sarcasm labels, which also limits redistribution while the Headlines licence is unchecked ([[Open Questions]]). Evidence: `session2` (commit 770f690, A3, p = 10%, seeds 0-2, dev only): mean dev macro-F1 w 0.1 = 0.8654 (sd 0.0068), **0.3 = 0.8691 (0.0045)**, 1.0 = 0.8608 (0.0045). w = 0.3 beats both other values on every one of the three seeds, so it is not a lucky seed; the "tie within ~1 std -> smaller w" rule does not apply because the paired seed-by-seed comparison is consistent. w = 1.0 is below A1 on all three seeds: too much weight on the helpers hurts the main task. - **2026-11-10** DELEGATED: **priority inside Pass 2.** Pass 1 shows the only gain is from the helper heads at 10% (+0.4 points), so the controls that explain that gain come first: A2 (heads on L only: is it the extra data in U?) and A8 (shuffled helper labels: is it the label content?). A6 (self-training) and A7 (FGM) matter less now that the GAN shows no gain, but they stay because a null GAN result is stronger next to a working SSL baseline. Budgets 1% and 10% only for the new arms (the 2x2 gets the full curve). Why: these are the contrasts the paper's main claim rests on; budget 30% / 5% for every arm would double the cost for little new information.
- **2026-11-10** DELEGATED: **Pass 2 arm specs.** A2 = A3 with the helper losses on L rows only and no U batch (same steps). A8 = A3 with the helper labels permuted at random across L + U (seeded; sentiment and emotion permuted independently), so class proportions stay but the link to each headline is gone. A6 = one round of self-training: the matching A1 run's model (retrained in the same job, same seed and steps) labels U; keep U items with confidence >= 0.9, then balance classes by taking the same number from each class; a fresh BERT trains on one L batch + one pseudo-labeled batch per step for the standard step count. Why one round and fixed 0.9: one round is the common baseline, and fixed rules avoid another tuning pass. A0 = TF-IDF on word 1-2 grams (sublinear tf, min_df 2) + logistic regression (C = 1, balanced class weights), no tuning. Why: A0 is a floor, not a competitor.
- **2026-11-10** DELEGATED: **analysis notebook scope.** Mean +- sd tables per arm and budget; paired bootstrap over test items for each contrast (resample test headlines 10,000 times, same resample across the 5 seeds, difference in macro-F1 averaged over seeds, 95% interval and two-sided p); F1-vs-budget figure; GAN training-curve figure; iSarcasmEval table. No multiple-testing correction beyond reporting all contrasts, stated in the paper. Why: the paired bootstrap uses the fact that every arm sees the same test items and labeled sets, which is far more sensitive than comparing seed means.
